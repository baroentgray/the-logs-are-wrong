# Automation and routing blueprint

This is a reviewed repository copy of the routing blueprint. BAR-34 implements deterministic local executor selection after task-packet preparation and before an explicit local lease lifecycle; it is not a dispatcher implementation.

1. A human or other approved read-only process prepares a local normalized JSON snapshot from authoritative references and an exact base SHA.
2. Run `dotnet run --configuration Release --project tools/Tlaw.Dispatcher -- packet --input <normalized-input.json> --output <task.yaml>` from the repository root.
3. The tool creates a compact `tlaw.agent-task/v2` YAML packet with links and paths, never copied Issue bodies, validates it, and replaces the output atomically only after validation succeeds.
4. A human may explicitly run `route` with a closed local agent snapshot. It validates an unclaimed task v2 packet, selects one eligible/capable/policy-permitted agent by availability-first ordering, and emits an internal `selection.json`; it does not create a claim or launch an agent.
5. A human inspects `selection.json`, then may explicitly invoke `lease acquire` with its `selected_agent` and an absolute local store path. The tool atomically prepares a validated claimed packet with a fencing token; it does not contact or launch that executor.
6. A human may explicitly run `ingest-result` with one claimed task/v2 packet, one result/v1 packet, and the existing local lease store. It accepts evidence only when task id, claimed agent, fencing token, and current lease state match exactly; it emits an internal record and the existing concise result projection without releasing the lease or changing any status.
7. A human may explicitly run `finalize-result` for a non-human `success` or `failed` result after ingestion. It releases only the matching active local lease and writes a deterministic record for a future adapter; it does not move Linear or complete a task.
8. A human may explicitly run `ingest-review` with a claimed task/v2, successful finalization record, review/v1 evidence, and an explicit reviewed head. It emits a deterministic future decision (`merge`, `correction`, or `human`) without contacting GitHub, moving Linear, or merging anything.
9. A human may explicitly run `ingest-handoff` with a claimed task/v2, correlated handoff/v2, an existing read-only local lease guard, and an approved reason. It records only a future `reassign` or `human` decision; it does not release a lease or select a successor.
10. A human may explicitly run `finalize-handoff` with the correlated claimed task/v2, handoff/v2, and handoff-ingestion record. It verifies exact byte-hash and identity evidence, deletes only the exact matching active or expired lease under the existing task lock, and publishes the same fully unclaimed task/v2. Timeout can retire an exact expired lease; manual cancel and quota exhaustion require an active one. It does not route, select a successor, acquire a new lease, launch an agent, or mutate Linear/GitHub.
11. The deliberate continuation chain is `prepare-handoff -> ingest-handoff -> finalize-handoff -> route -> lease acquire`. A human reviews each selected, prepared, claimed, ingested, finalized, review-decision, handoff-ingestion, or handoff-finalization record before any later, separately approved workflow step.
12. `linear snapshot` may read one minimal live Linear card through the official GraphQL endpoint and combine it only with a closed repository profile. It copies no description; its normalized output is accepted by `packet` before the existing route/lease sequence.
13. `linear transition` must re-fetch the exact snapshot immediately before its narrow state change, verify post-mutation state, and publish a deterministic receipt. `claim` holds and rechecks its exact active lease under the existing task lock through that mutation; `handoff` holds and rechecks an exact absent-lease guard through its mutation. A post-mutation guard failure reports that Linear may already have changed and never claims rollback. Merge accepts either local non-detached verifier evidence or exact-head detached CI evidence, but both still require evaluator PASS and independent Git ancestry plus exact `origin/main` proof. It may not merge or write GitHub. Review evidence alone remains unable to mark Done; the merge route requires separately verified Git and verifier facts.
14. `doctor` reports a closed adapter configuration as a route-compatible snapshot. It is readiness reporting only: no agent task launch, no project prompt, and no provider task execution. Grok's optional live readiness probe is headless, fixed, bounded and isolated; the local adapter is loopback-only.
15. `local-worker run` accepts only a fully claimed local `read_only_analysis` task, exact existing lease, closed config, and closed material manifest. It probes only the bounded loopback LM Studio model list and sends one no-tools/no-MCP read-only analysis request. It atomically writes only a non-authoritative `tlaw.local-worker-artifact/v1` outside the repository after lease rechecks; it never executes commands or changes task, lease, repository, remote-code-host, or Linear state.

16. A human or stronger model must inspect that untrusted artifact before explicit `local-worker complete --task <claimed-task-v2.yaml> --lease-store <absolute-path> --artifact <local-worker-artifact-v1.json> --output <agent-result-v1.yaml>`. The trusted host-side correlation reuses the strict artifact parser and response policy, holds the existing lock, rechecks the exact active lease before correlation and publication, and writes one deterministic `result/v1` success only when task, claim, artifact hashes, operation, metadata, non-authoritative, and no-command evidence agrees. It does not call LM Studio, alter task/lease/repository state, contact Linear/GitHub, or route anything. The manual chain is `local-worker run -> human/stronger-model inspection -> local-worker complete -> ingest-result -> finalize-result -> guarded linear transition to In Review`; finalization is `in_review`, never `Done`.

## Current limitations

The adapter may read Linear and perform only its guarded documented transition; it cannot write GitHub, merge, mutate branches, launch an agent, or send a provider task prompt. BAR-27's local worker is the narrow exception for an explicitly invoked loopback read-only prompt; it cannot alter the repository, remote code host, or Linear directly. It fails closed on GraphQL errors, stale snapshots, malformed evidence, non-loopback endpoints, and model-generated verification claims. Review ingestion and handoff finalization remain local evidence correlation and local lease lifecycle operations: they do not query a PR, create a review, imply merge completion, route a successor, acquire a successor lease, or launch an agent. Routing consumes only a provided snapshot: `AVAILABLE` ranks above `DEGRADED`, then a selectable preferred agent, then declared eligible order; `QUOTA_EXHAUSTED`, `OFFLINE`, and `UNKNOWN` are excluded. Preparing a packet, selecting an executor, acquiring/releasing a local lease, ingesting/finalizing evidence, probing readiness, or producing a BAR-27 artifact does not complete BAR-26.

Codex implements; Claude plans/reviews and can be a fallback executor; local tools prepare read-only evidence; Grok console/CLI supports experiments, research, red-team, and alternative review. No entry here launches an agent, locks a provider, changes authority, or grants implementation permission. `tlaw packet` is preparation only; `dispatch`, `review`, and `handoff` workflows require separate approval.
